# mFi MQTT Client

MQTT client for mFi power, current, voltage, and relay control. **Legacy mode is
the default** and preserves Home Assistant MQTT auto-discovery. Opt-in native
mode publishes the versioned mFi protocol for the native Home Assistant
integration instead; it never also publishes legacy discovery or subscribes to
legacy relay commands. An upgrade or identity provisioning does not select
native mode automatically.

## Usage

```sh
# Existing installations: legacy mode remains the default.
mfi-mqtt-client --config /etc/persistent/mfi-mqtt-client.conf

# Provision identity only; do not combine this standalone command with other options.
mfi-mqtt-client --initialize-device-id /etc/persistent/mfi-mqtt-client.conf

# Export the current legacy identities without connecting or running updates.
mfi-mqtt-client --config /etc/persistent/mfi-mqtt-client.conf \
  --ha-mode legacy --export-migration-map > migration-map.json

# Select native mode explicitly, after coordinating the ownership migration.
mfi-mqtt-client --config /etc/persistent/mfi-mqtt-client.conf \
  --ha-mode native

mfi-mqtt-client --help
```

Runtime requires `--server`, `--username`, and `--password`, supplied directly
or through `--config`; the broker port defaults to 1883. Provisioning and export
do not require broker credentials. `--no-update` disables the normally enabled
self-updater. `--ha_mode` and `--device_id` are aliases for `--ha-mode` and
`--device-id`.

## Configuration

Options can be provided via a TOML or INI configuration file passed with `--config`:

```toml
server = "mqtt.example.com"
port = 1883
username = "username"
password = "password"
polling-rate = 1000
log-level = "info"
# Native mode only, after provisioning and coordinated migration:
# ha_mode = "native"
# device_id is generated by --initialize-device-id; never copy one between devices.
```

The power refresh interval accepts 1-86400 seconds; expiration accepts 1-259200
seconds and must allow at least three refresh intervals. Polling must not be
slower than the refresh interval. Zero polling intervals are rejected. MQTT
service runs independently in short waits, rather than blocking for an entire
hardware polling interval.

## Persistent identity and migration export

`--initialize-device-id /absolute/config/file` reads the selected CLI
configuration, generates a random UUID v4 from OS entropy only when no ID is
present, and atomically persists `device_id = "<32 lowercase hex characters>"`.
An existing valid ID is reused **without rewriting the file**. Existing text,
comments, ownership and permissions are preserved; a new file is mode 0600.
The parent directory must already exist and be writable. Files are limited to
64 KiB; symlinks, hard links, non-regular files, duplicate/nested/malformed IDs,
concurrent provisioning and detected configuration edits are rejected.
Write/sync failures are errors, not permission to use an ephemeral identity.

This command prints only `device_id=...` to stdout and a persistence reminder
to stderr. It does not access hardware, contact MQTT, run updates, change
`ha_mode`, or run a flash utility. **On mFi, saving `/etc/persistent` still
requires a separately approved flash commit (`cfgmtd`) to survive reboot.**
Choose persistent storage; the client cannot verify filesystem persistence
across device reboots. Do not use `/tmp` in deployment.

Native startup and migration export require exactly one `--config` containing
a valid top-level `device_id` (or `device-id`). `--device-id` is only an explicit
selection/check of that persisted value: a CLI-only UUID or conflicting value
is rejected. Startup never generates/replaces identity. Hostname/label changes
do not change native device or physical port identities.

`--export-migration-map` requires legacy mode and supported hardware. It writes
a JSON object with `schema_version: 1`, `device_id`, `legacy_device_id`,
`legacy_full_id`, `legacy_availability_topic`, and `ports`. Each port has its
numeric `id` and a `roles` object keyed by `power`, `current`, `voltage`, and
`relay`; each role supplies `unique_id`, `discovery_topic`, and `state_topic`,
with `command_topic` additionally present for relay. These are derived from the
same initialized legacy functions that publish discovery, not guessed from
native IDs. No credentials are exported and nothing is published or deleted.
Compare the map against actual HA/broker inventory before an approved migration;
it is not itself a migration or a history-transfer operation.

## Native protocol v1

Supported boards currently enumerate eight ports for model ID `58952` and one
for `58993`. Descriptors use physical numeric sensor IDs starting at 1. Names
prefer the hardware label, then sensor name, then `Port <id>`; names do not
define identity. Board/port metadata is read at startup; restart after editing
it to reannounce a changed descriptor.

| Topic below `mfi/<device_id>/` | QoS | Retained | Payload |
|---|---|---|---|
| `config` | 1 | Yes | Descriptor with `schema_version: 1`, `device_id`, `name`, `manufacturer`, `model_id`, `model`, `firmware_version`, `publisher_version`, `refresh_interval`, `expire_after`, and `ports: [{id, name, capabilities}]` |
| `availability` | 1 | Yes | `{"session_id":"<32 hex>","state":"online"}` or `offline`, including Last Will |
| `port/<id>/state` | 0 | No | One report containing `session_id`, positive per-port `sequence` (at most `2^63-1`), and all four top-level role results |
| `port/<id>/set` | 0 | No | Exactly `{"session_id":"<current session>","request_id":"<32 lowercase hex>","value":"ON"}` or `OFF` |

Each role is `{"status":"ok","value":...}` or
`{"status":"error","reason":...}` with **no fallback value**. Successful
power/current/voltage values are finite, nonnegative numbers, rounded to four
decimal places; defensive maxima are 1e9 W, 1e6 A and 1e6 V. Relay values are
`"ON"`/`"OFF"`. Read errors are `open_failed`, `read_failed`, or `invalid_data`;
command confirmations can also report `write_failed` or `state_mismatch`.
A failed role does not hide healthy roles or other ports.

Changes and errors publish promptly. In native mode the existing
`--power-refresh-interval` (default 60 seconds) refreshes the **entire port
report**, including unchanged roles/errors; `--power-expire-after` (default 180)
is the descriptor's expiration for all roles. Reports never use cached values
as new readings. Shared online is gated by descriptor/offline acknowledgement
and completion of initial fresh reports, even when individual roles report
errors; consumers must check each role's status separately.

A new unpredictable session is generated **before installing Last Will on
every connection attempt**. Each attempt uses a new clean-session MQTT client;
old transport queues are discarded, sequence numbers restart at 1, and pending
confirmations are cleared. The existing bounded queue, five-second delivery
deadline, owning-thread processing and acknowledged shutdown apply to both
modes. No automatic QoS 1 command replay or command retry queue is introduced.

Commands reject the retained flag, wrong sessions, unknown ports, duplicate JSON
keys, extra/missing fields, invalid values and payloads over 512 bytes.
Malformed input never means OFF. Valid sets use checked writes only when the
observed relay differs or cannot be read; even unchanged ON/OFF requests receive
a fresh report with the matching `request_id`. Readback errors/mismatches are
not confirmations of success. A pending per-port confirmation rejects another
command until it can be published; servicing/reconnection never repeats the
hardware write. QoS 0 completion proves only a local socket write, not subscriber
receipt. Commands already sent can remain indeterminate after disconnect.

MQTT 3.1.1 clears RETAIN on live forwarding: the publisher can reject a
retained **delivery**, not detect a sender's retain bit once the broker removed
it. Controllers must publish once with QoS 0, no retain, no reconnect replay,
and the current session; never seed retained command topics. See the
[reviewed native integration plan](../docs/home-assistant-native-integration-plan.md)
for HA ownership and coordinated migration requirements.

## Legacy power freshness and availability

Power is published as `{"value": <watts>}` at QoS 0, **not retained**. Each
publication represents a successful read of that channel, including unchanged
100 W or 0 W loads. Discovery advertises `expire_after: 180` by default; normal
unchanged refresh is 60 seconds plus at most a polling cycle and scheduling
jitter. Changed quantized readings do not wait for the refresh interval.

Power discovery combines retained shared transport availability with retained
per-channel availability using `availability_mode: all`. The new channel topic
is `<existing sensor topic base>/availability` and uses the same
`{"availability":"online"}` / `{"availability":"offline"}` payload convention.
An unreadable, malformed, nonfinite, negative, or overflowing power value marks
that channel offline; it is never converted into zero or JSON null. Failures
are logged on transition, with recovery notifications, and do not stop other
measurements or outlets.

After reconnect, each channel starts behind an acknowledged offline gate.
Cached power is never replayed. A channel becomes online only after a new valid
read has been accepted for numeric publication and its availability transition
has completed. Accepted QoS 0 publication is **not** proof of subscriber receipt;
QoS 1 acknowledgements confirm broker acceptance, not subscriber processing.
Expiration remains the fallback for crashes, network loss, or stalled polling.

Current, voltage, relay state, and discovery retain their existing retention
policy. State topics, unique IDs, labels, units, and relay commands are unchanged.
A new subscriber may wait for the next successful power refresh; MQTT discovery
does not require server-side configuration changes.

The connector rejects disconnected/backlogged publications rather than building
an unbounded queue. Uncompleted MQTT publications have a 5-second transport
deadline, after which the connection and its old queued state are discarded.
Expiry measures receiver receipt time, not original sample age; arbitrary broker
delays cannot be detected without original timestamps.

## Shutdown and updates

SIGINT/SIGTERM request orderly shutdown. The client publishes retained shared
offline, services MQTT for up to 5 seconds for its PUBACK, and then disconnects.
If offline cannot be acknowledged, it logs the failure and closes without a
clean MQTT DISCONNECT so the broker can still use the Last Will.

Update checking/downloading runs in one background preparation job, keeping
polling and relay servicing active. Preparation has a shared 120-second deadline
and up to 5 additional seconds for owned downloader-child cleanup. Only applying
a prepared update briefly goes offline and replaces/re-execs on the MQTT-owning
thread. Termination cancels pending preparation and prevents a late result from
restarting the process. See [Self-Updating](../docs/updating.md).

## Existing retained power messages

Changing future publications to non-retained does **not** erase old retained
power. Do not consider an existing broker migrated until those exact legacy
records have been cleared through a separately approved operation. The client
does not purge them automatically. See the
[MQTT retained-state migration runbook](../docs/mqtt-freshness-migration.md).

## Host validation

```sh
cmake --preset local-debug
cmake --build --preset local-debug --target mfi-mqtt-client tests -j 2
ctest --test-dir build/local-debug -R 'native MQTT:|native_mqtt_wire_smoke|mqtt_wire_smoke' --output-on-failure

# Build the other executables before running their existing smoke tests.
cmake --build --preset local-debug -j 2
ctest --test-dir build/local-debug --output-on-failure
```

Native C++ tests cover descriptor/session rules, refresh/failed reads, strict
commands, readback confirmations, provisioning and legacy-map accuracy.
`tests/native_mqtt_wire_smoke.py` reuses the existing stdlib-only MQTT 3.1.1
fixture to run the executable against fake hardware and an ephemeral loopback
listener, with updates disabled. It covers default legacy/export parity, native
wire policies, late subscribers, reconnect/restart, descriptor-PUBACK timeout
and offline shutdown without PUBACK. It does not access live devices or HA,
verify MIPS procfs/flash behavior, or simulate arbitrary network congestion.
